# firmware/test/_shared/eval_forbidden_overrides.txt
#
# Per-feature eval.sh forbidden-modifications allowlist.
#
# Each line is one path (file or directory) that the eval gates'
# FORBIDDEN_PATHS check should IGNORE when it shows up in `git status
# --porcelain`. Used so that an authorized cross-cutting prompt (e.g.
# the Phase 2 orchestrator landing) doesn't trip multiple prior gates
# whose FORBIDDEN lists overlap the new prompt's surface area.
#
# Format:
#   - One path per line, repo-root-relative (same form as
#     `git status --porcelain` emits).
#   - Lines starting with `#` are comments; blank lines ignored.
#   - Leading/trailing whitespace stripped.
#   - Glob patterns NOT supported — list each path literally.
#
# Each override entry should carry a date + prompt-context comment so
# future readers can tell why it was added. Old overrides can be
# removed once their owning prompt's changes have been committed +
# baseline-rolled by `git update-index --assume-unchanged` or similar.
#
# Sequencing: the eval gates' FORBIDDEN_PATHS check parses each git
# status line, strips its " M " / "?? " / etc. prefix, and looks up
# the resulting path here. If matched, that file is allowed; if all
# changes under a forbidden directory are allowed, the directory
# itself passes.
