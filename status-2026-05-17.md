# Status — 2026-05-17

## [MAC] Phase 2 bug fixes + HIL preflight rerun

**Scope:** address the 3 orchestrator/shadow bugs caught at the
2026-05-12 HIL Phase 3 attempt on the dev RS7. The ECU returned
`7F 27 12` (subFunctionNotSupportedInActiveSession) when the
orchestrator sent `27 11` SecurityAccess directly in DEFAULT
session — proving the orchestrator was missing a `10 02` programming
session entry before SA. Halt safety preserved on that attempt
(zero `31 01 FF 00` frames on the wire) but the SA call died at
recv timeout (rc=263) instead of cleanly bailing on the NRC.

**Three bugs surfaced and addressed in this session:**

- **Bug 1** — orchestrator emits `27 11` SA without prior
  session-control. Fix: insert the full MM-style pre-SA preflight
  procedure (3 cycles with 2 hard ECUResets, per
  `MM_Flash_Capture_Analysis.md` §2.1).
- **Bug 2** — `uds_recv_skip_pending` returned ESP_OK on any
  non-pending response, masking the NRC bytes from the operator.
  Fix: new `MDG1_FLASH_PHASE_NRC_RECEIVED` progress event carrying
  the original SID + NRC code; orchestrator emits it before the
  generic FAILED event whenever a non-pending NRC arrives.
- **Bug 3** — shadow harness unconditionally answered `67 11`
  to any SA seed request, masking Bug 1 from the host harness.
  Fix: shadow now tracks ECU session state (DEFAULT / EXTENDED /
  PROGRAMMING) and returns `7F 27 12` for SA-in-DEFAULT.

**Scope expansions called out at clarification points (not all in
the original "fix 3 bugs" ask):**

1. The cal-only flash capture (`mm_MAPS_upload.log`) doesn't do
   the ECUResets and SA still works in that log. After Sean's
   correction that cal-only assumes a prior FULL-flash unlock by
   the same tool in the same session, the orchestrator implements
   the FULL preflight always — what works on a fresh customer ECU.
   `MDG1_PREFLIGHT_CYCLES_BEFORE_SA = 3`,
   `MDG1_PREFLIGHT_ECURESET_BEFORE_CYCLE = 2`.
2. Per Sean's follow-up question on flash-eligibility detection:
   added F1 5B (programming history rolling log) read during
   preflight cycle 0. Compares entry[0] to
   `MDG1_PROG_FINGERPRINT_BYTES`; on match → cal-only-allowed,
   else → FULL required. Surfaced via new
   `MDG1_FLASH_PHASE_ELIGIBILITY_DETECTED` progress event AND
   written back to `plan->cal_only_allowed_out` so a UI caller
   can read the decision after the run. The unlock procedure
   itself is always FULL; detection only gates the UI-side
   flash-type option.
